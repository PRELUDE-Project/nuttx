# H753のカード識別・SCR診断（実機未検証）

この診断はSD単体検証の第一段階です。カードの識別情報とSCRを取得します。セクタの読取り・書込み、ファイルシステム、速度測定、異常後の復旧は試験しません。既定では無効です。

## 対象と制限

- `CONFIG_SD_RECEIVE_LEASE_ONLY_REVIEW` はH753向けの既存SCR隔離実装、IDMA、readonly設定を必要とします。
- MMC対応、raw ioctl、FAT、mountを無効にします。診断構成ではumountとdd、別のSDMMC_CHECK試験アプリも除外します。
- 受信は有効なSCR所有権で指定された恒久領域への8バイトだけです。同じ所有権での二重setupも拒否します。一般のセクタ読取りには使用できません。
- エラー後の領域は再利用しません。IDMAの物理停止や旧IRQの排出を証明する機能ではありません。
- 操作にはカード識別・選択・クロック変更が含まれます。すべて400kHzで動く、カード状態を変えない、という意味ではありません。
- 対象のH7 driverは4BIT_ONLYを返しません。診断はSCR取得後に終了し、その後のwidebus切替を行いません。

## アプリの配置

`app/` はNuttX Apps用のソースオーバーレイです。このリポジトリ内に保存して変更を同じコミットで追跡します。別のAppsリポジトリを自動更新するものではありません。

検証したAppsの基準は `8ff533beb37eeef1f288c467acd7c50b542464eb` です。承認された作業コピーの `system/scrdiag/` に `app/Makefile`、`app/Make.defs`、`app/scrdiag_main.c` を配置します。既存ディレクトリや変更を上書きせず、まず差分を確認してください。既存の `system/Make.defs` のwildcardから登録されます。独自のApps Kconfigは不要です。

公開APIは `include/nuttx/mmcsd_scrdiag.h` です。アプリの `sdio_initialize` / `sdio_mediachange` はH753向けのアダプター依存です。別機種への移植可能性は確認していません。APIは信頼されたtask context専用で、raw ioctlとして公開しません。

## ビルド構成

`diagnostic.config` は既存の確認済みH753構成へ適用する**差分**であり、単独で使用できるdefconfigではありません。最終的なチップ、ボード、クロック、AXI SRAM配置、キャッシュ無効、割込み構成を確認し、olddefconfig後の設定を保存してください。診断入口にはMMCブロックデバイスの登録やmedia callbackを使いません。

現在のARMビルドはH753チップとnucleo-h743zi2派生BSPによるレビュー構成です。実ボードとの電源・クロック・ピン・revisionの適合確認は別に必要です。ビルド成功は実機の動作保証でも書込み承認でもありません。

公開ブランチの対象BSPには自動SD初期化を追加しません。検証用のローカルビルドfixtureには `CONFIG_SD_PRODUCT_BUILD_ONLY` による初期化がありましたが、診断設定時は抑止してビルドしました。このfixtureは本変更の公開対象ではありません。起動時に診断を自動実行するスクリプトを追加しないでください。

## 実行前と終了条件

実機を接続・書込み・起動する前に、配線、3.3V電源、プルアップ、逆給電防止、カードとMCUの個体、既存flashとカードデータの保全、必要な承認を確認します。この変更自体はその承認になりません。

条件が満たされた場合に限り、手動の `scrdiag` 入口を使います。引数はありません。入口は実際のカード検出をしていません。操作者が現物を確認したという前提でpresenceを設定します。ソフトウェアのone-shotフラグは、成功・失敗とも再初期化前の再実行を拒否します。これはSCR所有権とは別の起動制限です。

終了時はカード識別・SCR結果と、取得できた世代付き診断ログを保存します。snapshot、DATAEND単独、ポインタNULL、ソフトresetを停止証明にしないでください。エラー後は再試行や領域の再利用をせず、物理停止条件を解決するまで隔離を維持します。故意の抜線・短絡・通電中のカード抜去はこの試験に含めません。

## 検証範囲

手動入口と上位入口の実関数を抽出したホスト回帰で、初期化・attach・識別・非SD・SCRの各失敗と再実行拒否を確認しました。下位の実デバイス処理はstubです。有効・無効両設定でARMビルドを確認し、有効ELFにprobe/slotinitialize/FAT/mountの入口が残らないことを確認しました。

構造体のSDIO基底はoffset 0を静的検査します。ホスト回帰やクロスビルドは、実機の停止保証・実時間動作・配線の安全性の代わりにはなりません。
