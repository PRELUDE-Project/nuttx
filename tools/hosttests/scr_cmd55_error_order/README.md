# SCR取得：CMD55失敗と受信取り消しのエラー優先順位

[NuttX固定版 `7965c77a`](https://github.com/PRELUDE-Project/nuttx/tree/7965c77ad63db5ed14506ca19f112ac6df04fa7e) のホスト回帰です。SCRを取得する上位処理と、STM32H7のコマンド送信・取り消し・SCR受信終了処理をつなぎ、先に発生したエラーが呼び出し元へ返ることを確認します。

```sh
python3 run.py /path/to/pinned-nuttx
```

Python 3とUBSan対応のGCCを使います。実装2ファイル、ヘッダー1ファイル、既存試験の3ファイルのGit blobを照合し、ソースの該当範囲から一時ファイルを作ります。GCC 14.2.0、`-O0`／`-O2` の両条件で確認しました。

| ホストで再現した順序 | 呼び出し元への戻り値 | 受信領域に保持する終了理由 |
| --- | --- | --- |
| データ受信がタイムアウトした後にCMD55を送ろうとし、送信が拒否される | `-ETIMEDOUT` | `-ETIMEDOUT` |
| CMD55の送信後、応答待ちが先に `-EIO` となり、その後に受信を取り消す | `-EIO` | `-ECANCELED` |

両ケースで通知は1回、呼び出し元の8バイトは変更されず、模擬の受信先は切り離され、受信領域の再取得は `-EBUSY` でした。ただし、模擬IDMAの動作許可ビットは残っています。再取得の拒否を、実機でDMAが停止した証拠とは扱いません。

タイムアウトの呼び出しは同期で注入し、応答待ちの失敗は代役で与えています。対象は既存ホスト試験設定のSCR処理に限ります。実際の割り込み順序、カードやDMAの動作、セクター操作を無効にしたH753向けイメージ、対象ボードは未検証です。
