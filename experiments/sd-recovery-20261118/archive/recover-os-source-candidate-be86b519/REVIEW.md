# 固定OSソース向け通知APIの未公開候補

固定task_recover.cに対する差分 task_recover.patch、変更後task_recover.c、新規header recovery_watch.hを作成した。従来のhost専用登録処理を、明示的な新規API nxsched_recovery_bind_locked/unbind_locked として定義する案である。これは既存NuttXにあるAPIではない。既存ファイルへ実装を置くため新たなMakeソース登録は不要だが、新規headerとdriver側利用箇所の統合は必要。

CONFIG_SD_SECTOR_READ_REVIEWでのみ登録表とrecover入口通知を有効にする案。recoverの通知区間には明示criticalを追加。登録/解除のlocked APIはTCB取得から呼出までの外側criticalを要求し、static node・同期callback・callback中のlifecycle再入禁止を明示した。登録表の処理は既存export統合host TUへ接続し、Werror/UBSanで正常SCR、無効引数、TCB欠落、sector終了隔離の既存回帰を通した。

重要: task_recover.c全体のターゲットコンパイルはしていない。host回帰は登録表処理とdriver接続であり、新規header・完全OS TUのビルド証明ではない。新規ファイルへのAPI抽出は名前をhost用へ置換した比較であり、ARM ABIを検証しない。

製品反映の阻害: 汎用的な再入をDEBUGASSERTだけで抑止する設計は未解決。通知中に別タスクを終了させるcallbackは許容できない。対象構成で当該SD callbackからその経路がないことと、SMP/高優先割込み/tickless/instrumentation等の適用制約をcompile時に確定する必要がある。全recover callerの網羅、raw helperの製品全TUでの不可視化、実TCB寿命、正式H753設定、対象ARM build、物理停止も未完。

このため本候補は製品ブランチへ反映していない。設計試案を固定OSファイルへ具体化した段階であり、安全性完成とは扱わない。実機操作、新規導入、APT/WSL拒否の迂回なし。

## 構成制約の実装と検査
PR #1を再取得しbe86b519/open/draftを確認。固定wd_cancelはwdog spinlock内のsched_note_wdogと、unlock後のnxsched_reassess_timerを呼ぶ。参照構成でそれぞれ無効化されることを既存原典で再照合した。未検証構成への誤適用を防ぐため新規候補headerへSMP、HIPRI、TICKLESS、SCHED_INSTRUMENTATION、IRQCOUNTを拒否するcompile gateを追加した。IRQCOUNT拒否は危険と断定したためではなく、検証済みBASEPRI直結経路に限定するため。

host前処理でsector OFF/ON×無追加/各5設定の12組合せを実行。sector ONの禁止5組合せは指定errorで拒否、OFFの全6組とON単独は通過。これは正式Kconfigの検証・対象ARMビルドではなくheader gate単体試験。gate-results.json保存。

compile gateはcallback再入を一般に解決しない。現在の公開的bind APIへ別callbackを登録できる設計のままでは、限定SD callbackのcallgraph確認だけで汎用安全性を主張できない。製品適用には登録対象を限定するAPI設計または全callback契約の実証が必要。今回も製品反映は保留。
