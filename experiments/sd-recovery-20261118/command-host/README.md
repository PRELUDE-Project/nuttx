# scrdiag コマンド入口のホスト試験

対象はセクタ読取り用H753ビルドで使った `scrdiag_main.c`（Git blob `18c8ad3cb0ca92d95d230db52f268d4dbf078209`）です。対象ソースをそのままコンパイルし、SDIOを直接呼ばずに初期化・通知・SCR・セクタ読取りの呼出し順序と回数を観測しました。

- 負号、正号、16進接頭辞、空文字、空白、末尾文字、32 bit上限超過、NULLのLBA、および `write` 指定は、割込み保護区間にもSDIOにも入らずに拒否します。
- セクタ機能ありでは、正しい引数を1回だけ受理します。SCRが失敗した場合はセクタを読みません。機能なしではセクタ指定を拒否し、SCR単体を実行できます。
- `-O0` と `-O2` で、機能の有無と各3条件を組み合わせた計12件が通りました。[ログ](command-host.log)

`sh run.sh <対象ビルドのapps/system/scrdiag/scrdiag_main.c>` で再現できます。LBAの32 bit上限を確認したのは引数処理までです。媒体の容量判定、物理カードへのアクセス、IDMA停止、破損防止をこの試験で証明したわけではありません。
