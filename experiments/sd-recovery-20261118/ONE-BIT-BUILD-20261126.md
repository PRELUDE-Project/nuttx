# NUCLEO-H753ZI：SDMMC 1ビット読出し診断の対象ビルド

4ビット版を残したまま、初回の配線確認と4ビット転送の切り分けに使える1ビット版を別にビルドした。既存の `c1fb8bed` ベースのH753ZI向け診断構成（[対象ビルドの記録](QUICKSTART.md)）と同じソース・ツールを使い、転送幅の設定だけを変えた。SDMMC1、IDMA、SCR診断、1セクター読出し、読み取り専用設定は維持した。

| 項目 | 4ビット版 | 1ビット版 |
| --- | ---: | ---: |
| `nuttx.bin` のサイズ | 136,356 B | 136,324 B |
| リンカ報告のSRAM使用量 | 8,560 B | 8,560 B |
| `sdio_initialize` からのGPIO設定呼出し | 6 | 3 |

`CONFIG_SDMMC1_WIDTH_D1_ONLY` という設定名だが、1ビット版が使うデータ線は **DAT0** であり、DAT1ではない。固定ソースではDAT0（PC8）、CLK（PC12）、CMD（PD2）のみを設定する。ドライバーは1ビット専用を上位に通知するため、カードが4ビットをサポートしていても、4ビットに切り替える処理に進まない。

再現には [既存のH753ZIビルド手順](QUICKSTART.md) を使う。1セクター読出し用 `defconfig` のコピーで、未設定の `CONFIG_SDMMC1_WIDTH_D1_ONLY` を `=y` に変更してから新規ビルドする。今回使ったArm GNU Toolchainは15.2.Rel1。生成設定を比較した結果、ビルドディレクトリを示す `CONFIG_BASE_DEFCONFIG` を除き、差分は [転送幅の1項目](one-bit-config.diff) のみだった。[検証ログ](ONE-BIT-BUILD-20261126.log) に両版のELF・BINのSHA-256とGPIO設定の照合結果を記録した。

このビルドは、カードやアダプターのプルアップ、電源、配線が適切であることを保証しない。内部プルアップは両版とも無効のまま。実機での書込み、カードの読み出し、およびIRQやIDMAの停止確認は行っていない。
